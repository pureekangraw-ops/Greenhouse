# Genome and Lyra v1

Approved direction: Genome derives from SPECTRUM; Lyra is designed for Observatory Inside/Outside View. Both are assistants, not owners of Work or device truth.

Genome has distinct SHOP and OFFICE modes. SHOP captures a brief, uses supplied catalogue evidence, and sends commercial/payment/human requests for review. OFFICE reads existing Work/checkpoint evidence, identifies blockers, prepares handoffs and returns source-backed summaries. Customer text and Office context never share a session.

Lyra consumes a foreground WebView snapshot or map evidence. Browser proposals reference device/tab/capture/revision/epoch and expire within 30 seconds. Map proposals distinguish approximate areas from verified exact coordinates. It never claims browser dispatch, map rendering, or arrival succeeded without a destination readback.

Implement a server-side agent library: role prompts, deterministic evidence/authority preflight, injected model provider and structured output validation. Provider content is untrusted and cannot grant authority. No default endpoint, credential, identity, Work or commercial truth is created. The model drafts a reply; trusted policy determines the action. There is no automatic execution.

Acceptance: offline scenario tests cover changed scope, incomplete intake, commercial claims, owner context, stale browser capture, prompt injection, uncertain coordinates and mismatched receipts. Provider fixtures prove the runtime boundary only. Actual model evaluations and Hub/device E2E remain UNKNOWN until a provider and owner adapters are available.
